# 精灵艺术绘制规范

> 给写 `src/render/sprites/art_*.rs` 的人看。**先读完这一页再动手。**

## 为什么这件事重要

这支片子被用户判定「看不懂画的是什么」「和简笔画一样小学生水平」。
原因不是字符画这种形式，而是**画得不像**。

对标作品（MisakaZentai/world-execute-me-dsh-pv）之所以好看，
是因为它每个镜头画的都是**一眼能认出的具体东西**：一只蝴蝶就要有蝴蝶的翅形和触角，
一棵松树就要有层叠的三角树冠，一片雪花就必须六角对称。

**「像不像」是唯一的验收标准。** 不要糊弄，不要用一团方块代替形状。

## 文件骨架

每个季节一个文件，例如 `src/render/sprites/art_spring.rs`：

```rust
//! 春之精灵。
//!
//! 每个精灵的 `art` 是逐行手绘的字符画：先想出这个东西的轮廓，再用字符填。

use super::Sprite;

/// 蝴蝶：两对翅（上翅大、下翅小）、细长身体、一对触角。
pub static SPRING: &[Sprite] = &[
    Sprite {
        name: "butterfly",
        art: &[
            "   .       .   ",
            // ... 每一行一个字符串
        ],
    },
    // ...
];
```

**注意**：`static` 名必须是 `SPRING` / `SUMMER` / `AUTUMN` / `WINTER` / `COMMON`，
与文件名对应。`Sprite` 从 `super` 导入（定义在 `src/render/sprites.rs`）。

## 字符约定（覆盖度）

| 字符 | 含义 | 覆盖度 | 用途 |
|---|---|---|---|
| `' '` | 空 | — | 留白 |
| `'.'` | 最暗 | 0.55 | 暗部、边缘、绒毛 |
| `':'` | 次暗 | 0.72 | 中间调 |
| `'*'` | 中 | 0.88 | 亮部 |
| `'#'` | 实心 | 1.00 | 最亮/实体 |
| `'+'` | 高光 | 1.00 | **用第二色**（露珠反光、花蕊、月晕） |

**最暗的 `.` 也给到 0.55**——Braille 只在 `w > 0.5` 时点亮，给 0.2 整块都不亮。

## 硬性要求

1. **尺寸**：9~21 行，11~31 列。行宽可以不齐（渲染时按最宽行算），但**别差太多**。
2. **必须有 20 个以上墨点**（非空格字符）。
3. **不许出现 tab**，只用空格对齐。
4. **该对称的必须对称**：蝴蝶、雪花、枫叶、莲叶、酒盃、蜻蜓、梅花、菊花。
   写完请自己逐行数一遍左右是否镜像。
5. **用满四个暗阶**：全用 `#` 会变成一坨黑影，全用 `.` 会糊成灰雾。
   亮部 `#`、中间 `*`、暗部 `:`/`.`，才有体积。
6. **每个精灵前写一行 `///` 注释**说明画的是什么、关键特征是什么。

## 一个画好的样例（蝴蝶，14×15）

```
"  .         .  ",   ← 两根触角，向外张开
"   .       .   ",
"  ..*     *.   ",
" .***** *****. ",   ← 上翅展开
" .***### ###**. ",
"  .***** *****. ",
"   .***   ***.  ",
"    .*     *.   ",   ← 身体
"    .#     #.   ",
"     .#   #.    ",
"     .#####.    ",
"      .###.     ",
"       .#.      ",
"       ...      ",
```

（上面只是示范格式与画法，**不是让你照抄**——你要自己画出更好的。）

## 自检

写完用这个命令做**纯语法**自检（不编译、不写文件）：

```bash
rustfmt --edition 2021 --emit stdout src/render/sprites/art_XXX.rs > /dev/null && echo OK
```

**严禁**运行 `cargo` / `rustc` / 任何编译命令——用户明确要求编译全部交给 GitHub Actions，
本机不许占 CPU。**严禁**在 `/tmp` 写文件（tmpfs 撑爆过一次，会话 bash 失效两小时）。

## 交付

只写你自己那一个 `art_*.rs` 文件，不要碰任何其它文件。
完成后把「精灵清单（名字 + 行数 × 列数）+ 你对每个精灵的可辨认设计要点」发给 lead。
